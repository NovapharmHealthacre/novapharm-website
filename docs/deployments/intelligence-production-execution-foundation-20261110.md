# NovaPharm Intelligence | execution role and private log foundation

**Scope:** Provision the least-privilege image-pull/logging identity for future ECS/Fargate service. This is not a customer login, production task, inference service, paid subscription or regulatory data acceptance.

## CloudFormation
`infra/aws/intelligence-production-execution-foundation.json` creates exactly:
- One named CloudWatch Logs group `/aws/ecs/novapharm-intelligence-production`, with 30-day retention and non-customer-runtime tags.
- One ECS-task-assumable IAM **execution** role. It can request ECR authorization tokens (AWS requires wildcard resource here), pull image blobs **only** from `novapharm/intelligence/production`, and write to the exact new log group. It cannot read application secrets, patient/customer records, Cognito users, AI credentials, Atlas or billing data and cannot publish an image.

The future **application task role is separate** and cannot be assigned these permissions as a substitute for tenant-bound data authorization.

## Deployment/recovery
CloudFormation stack `novapharm-intelligence-production-execution` can be created only after verifying the log-group name and confirming role trust/policies. The IAM role has an autogenerated physical name; CloudFormation requires `CAPABILITY_IAM`. Review the exact change set before execution. On rollback, delete the stack only after verifying no task definition/service relies on it and preserving required audit logs. No compute is started by this stack.

## Remaining gates
S3 image-layer gateway exists but ECR `api`, `dkr`, CloudWatch Logs and Secrets Manager **interface** endpoints still need to be created with budget acceptance and security-group restrictions. The application also needs customer OIDC MFA/session binding, protected API, source-rights registry, complete data, NOVA and Stripe entitlement reconciliation before customer activation. Never promote candidate images merely because the execution role exists.
